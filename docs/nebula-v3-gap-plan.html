What the v3 mock draws that the client doesn't

Forty things the Fancy Mumble 2026 v3 canvas shows and the Nebula pack does not have today, each placed in the part of the window it belongs to and checked against the pack's own source. The largest single block is the server rail, which is not a variation on anything Nebula currently draws — it is a new column in the window.

01

The server rail

left of the 290px sidebar

The mock puts a 56px vertical rail at the far left of the window and hangs the whole multi-server story off it. Nebula has no rail: SidebarShell is the leftmost column, and ServerList.tsx is the connect screen's list of saved logins, not a rail. This is the one zone that changes the window's column model, so everything in it lands together.

missing

The rail itself

In the mock

A 56px column: a pin toggle at the top, one tile per connected or saved server, a + tile, and a disconnect control at the bottom. It survives every screen — chat, friends, connect, settings.

In the client

No rail. The window is title bar, then the 290px sidebar, then the pane. Server switching lives in the title-bar pill and on the connect screen.

The build order

seven passes and a decision

Ordered by what unblocks what, not by size. Two constraints set the sequence: the rail changes the window's column model, so it goes first and alone; and the timestamp correction moves the width of every time column, so it lands before anything new is drawn against those columns.

01

The server rail

Its own pass, because it adds a column every other screen has to live beside. Build the shell and tile states first — the rest hangs off a model that has to exist anyway.

  • Rail shell and tile states, then the unread pip; a rail model in selectors.ts joining saved groups, live sessions and per-server unread.
  • Hover card with its three bodies, reusing the livery data ConnectScreen already loads.
  • Pinned panel — the same model at a second width.
  • Drag to reorder, persisting to the serverTabOrder preference that already exists.
  • Add-server prefill — a two-line change, but it belongs with the rail's “+”.

sidebar/ServerRail*.tsx NebulaClientApp.tsx selectors.ts connect/AddServerDialog.tsx

02

Times and format

Small, and it has to precede the message-list work: 12-hour time is wider than 24-hour, so every new row drawn against a timestamp column would otherwise need re-measuring afterwards.

  • Point formatTime, the day divider and the relative date at the shared formatter instead of the browser's defaults.
  • Add the server time switch and its “Now showing:” line to Language & format.
  • Check the lightbox and the activity log follow too, not just the message rows.

selectors.ts settings/LocalizationSettings.tsx

03

The message list

Pending and failed rows come first — today a failed send loses the text, which is the only item on this list that costs a person something.

  • Pending and failed rows, in whichever message style is set, without shifting the conversation when they resolve.
  • Mention popovers — wire the person case to the existing card, then draw the group list.
  • Who has read this and open image in its own window on the message menu, plus the quick-reaction row above the divider.
  • Typing indicator — Nebula already sends it; render what the store holds.
  • Link preview card, leaving its Watch-together button behind whatever the decision below settles.

chat/MessageList.tsx chat/MessageRow.tsx chat/MessageMenu.tsx chat/PendingMessageRow.tsx chat/MentionPopover.tsx

04

The channel header and its panel

The info panel is the largest new surface after the rail, and the trust badge wants somewhere to lead — so the panel lands first and the header items follow into it.

  • Channel info panel as a full-window surface alongside pinned, downloads and server info; the key-ownership block needs the most room and the most caution.
  • Encryption and trust badges beside the channel name, four levels, leading into verification.
  • News marks on the kebab and inside it, clearing on open.
  • Fill out the kebab: mute channel, move everyone out, channel info.

?

Decide before any of it: watch together

The mock draws the host side in three places — the link card, the header kebab and the dock menu — and nebula/ARCHITECTURE.md lists “Watch together, host side” as deliberately out of scope. Passes 03, 04 and 05 all touch a menu that would carry its entry point, so settling this first avoids building those menus twice. If it stays out of scope, the link preview card in pass 03 ships without its button.

Already at parity — don't rebuild these

  • Title bar, including the “+” menu with recents and their occupancy
  • Mini mode
  • Connect screen livery — banner, icon, tagline, MOTD, tags, rules link

  • Composer: reply stack, staged files, upload tray, polls, GIF, emoji, format bar

How this was derived. Every item was read off the Fancy Mumble 2026 v3.dc.html canvas and then checked against crates/mumble-tauri/ui/src/ui/nebula on develop — the pack's own source, not the older nebula-parity-spec.html, which compares Nebula against Standard rather than against this mock. Where a feature exists in Standard but not in Nebula it is recorded as missing here, since Nebula is what the mock describes.

One gap in the source. The canvas file is larger than the design API returns in a single read, so the last stretch — the Admin section's Users and Onboarding sub-pages, and the state script at the end — was not readable. Both admin pages already exist in the client (UsersAdmin.tsx, OnboardingAdmin.tsx), so the risk is small, but this list may be short by whatever those two pages changed.
