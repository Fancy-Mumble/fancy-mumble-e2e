What Standard does that Nebula doesn't

Twenty-four things a person can do in the Standard client and cannot do in Nebula, each placed in the window where it belongs and described down to its states. This is the work list — the features already recorded as deliberately absent in nebula/ARCHITECTURE.md are not on it.

House rules

These hold for every drawing below, and they are already true of the pack — a screen that breaks one will look wrong next to the ones beside it.

Corners

Four steps: 6 inset detail, 10 controls, 14 surfaces, 20 overlays. Pick by what the element is, never by eye. Circles and pills are shapes, not radii.

Two schemes, one accent

Nebula follows the user's colour theme for light/dark and its accent, so every state colour has to hold on both grounds. Design each screen twice.

Glass is chrome only

Title bar, sidebar and channel header blur what's behind them. Cards and panels sit on the window colour and don't. Don't glass a card.

Panels, not pages

Nebula covers the shell with one full-window surface at a time — pinned, downloads, server info. New surfaces join that set rather than opening a second window.

Settings is one nav

User settings and server administration share a single sidebar. A new control belongs on an existing page; a new page needs a line in that nav.

Copy is sentence case

Menu items and buttons say what happens. Micro-labels above groups are the only uppercase, and they carry letter-spacing.

Where the work is

Nebula's window, to scale, with the count of open items per zone. Fourteen of the twenty-four are in the shell you see here; the rest are in settings, on the connect screen and on the profile card, which cover this layout rather than sit in it.

How to read an item

Every item carries one of four tags. They say what kind of drawing is wanted, which is usually a better guide to effort than the item's size.

Surface

A whole panel or dialog that doesn't exist yet. Needs layout, empty state and dismissal.

Control

A control on a page that already exists. Match the controls beside it.

State

An indicator on something already drawn — a badge, a dot, a row variant.

Defect

Already reachable, already wrong. Nothing new to invent; something to correct.

Title bar & server rail

Nebula stacks connected servers as tiles down a rail and puts the "+" in the title bar. Standard lays them out as a horizontal tab strip. The rail is the better shape — what it is missing is everything the strip carries besides identity.

State

Unread counts and tab order on the server rail

A rail tile shows which server it is and nothing else. There is no unread count, no way to reorder the servers, and disconnecting has no confirmation.

Must show
  • An unread count per server, legible against the tile's own hashed colour and truncated above 99.
  • A drag affordance for reordering, and where a tile lands while dragging.
  • A disconnect confirmation naming the server, with a "don't ask again" checkbox.
States
  • active
  • connected, unread
  • connected, quiet
  • connecting
  • dragging
  • drop target
Data
Order persists to the serverTabOrder preference, which already exists and is already migrated from the old local-storage key. Sessions arrive in backend order; unlisted ones append.
Placement
On the 56px rail. The count has to work at tile size, so a corner pip is more likely than a trailing number.
Standard
components/layout/ServerTabsBar.tsx

Sidebar

Four gaps: two are dialogs the channel tree needs before an action can complete, one is a search result type that has nowhere to render, and one is layout state that resets on every launch.

Surface

Password prompt for a protected channel

Joining a password-protected channel currently fails silently — nothing asks for the password. Nebula already prompts for a server password and a TOTP code; this is the same moment one level down.

Must show
The channel's name set apart from the sentence around it, one password field, "Join" and "Cancel", and a wrong-password state that keeps what was typed.
States
  • asking
  • submitting
  • rejected
Data
joinChannelWithPassword(channelId, password). The channel entry carries the name.
Placement
Window-root dialog. LeaveServerDialog and LinkWarningDialog are the two precedents to match — both set the thing being acted on apart from the prose.
Standard
components/sidebar/channel/ChannelPasswordDialog.tsx
Surface

Move everyone out of a channel

A moderator can move one user from that user's menu. Clearing a whole channel means repeating it once per person.

Must show
Which channel is being emptied and how many people that is, a searchable destination picker over every other channel, and a confirm that names both ends of the move.
States
  • picking
  • no destinations
  • moving
  • partially refused
Data
moveChannelUsers(sourceId, targetId). Eligible destinations are every channel except the source.
Placement
Entered from the channel's context menu, under the existing moderation items. Nebula's user menu already has a "Move to channel" picker — reuse its list, not a second design.
Standard
components/sidebar/move/MoveUsersDialog.tsx
Surface

Pictures and links in search

Nebula's search finds channels, people, messages and servers. Standard also searches shared pictures and links, and with an empty query the pictures filter becomes a browsable grid of everything shared in the channel.

Must show
  • Two more filters beside the existing ones: Pictures, Links.
  • A picture grid that pages 20 at a time as the reader reaches the bottom, with a placeholder tile per image until it decodes.
  • A link result that leads with the host, since that is the part worth reading — the same reasoning as the link warning dialog.
States
  • grid, loading first page
  • grid, paging
  • grid, end reached
  • no pictures
Data
get_photos, paged, deduplicated by source. Link results come back with the message they were found in.
Placement
Inside the existing search results, which today assume a single list of rows. The grid is a second shape that list has to be able to become.
Standard
components/sidebar/SidebarSearchView.tsx
State

Remember collapsed sections and the open tab

Collapse a sidebar section and it comes back open next launch. Two preferences already exist for this and Nebula writes neither.

Must show
Nothing new — but the collapse affordance has to read as a persistent setting rather than a momentary one, which usually means the chevron animates and stays put rather than snapping back.
Data
sidebarSections, sidebarActiveTab.
Placement
Sidebar section headers.

Channel header

Nebula's header is deliberately two glyphs wide — search, then a kebab. That decision is sound and these four items should not undo it; three of them are about what the header can say without growing, and one is a panel behind it.

State

Encryption state and key trust

Nebula runs the persistent-chat machinery and honours a revoked key by disabling the composer, but it never says whether the open channel is encrypted, whether its key is trusted, or offers a way in to verify one. The trust level is already computed and thrown away.

Must show
  • Whether this channel persists its history, and whether it is end-to-end encrypted — two facts, not one badge.
  • Key trust at four levels, distinguishable without colour alone.
  • A way to reach the verification dialog from the badge itself.
States
  • Verified
  • Manually verified
  • Unverified
  • Disputed
  • not encrypted
  • not persisted
Data
usePersistentChat() returns trustLevel and sendBlocked today; Nebula uses only the second. Disputed is the one that must be impossible to miss.
Placement
Beside the channel name in the 66px header, at the scale of the existing subtitle. Verified is the common case and should be quiet; disputed should not be.
Standard
components/security/KeyTrustIndicator.tsx, mounted in ChatHeader
Surface

Channel info panel

The header's "Info" item opens server info. There is no way to read a channel's own description, see who is in it including people currently offline, or deal with its encryption keys.

Must show
  • Name and description — rich text the server sends, which may be long and may contain images.
  • Members, split online from offline, each row opening the same menu the roster does.
  • Key ownership: who holds this channel's keys, and a reset with two modes — keys only, or a full wipe — each with a plain-language consequence, since one destroys history.
  • Channel id and whether the viewer can delete messages here. Raw permissions only in developer mode.
States
  • reading
  • editing name/description
  • saving
  • no description
  • no members
  • refreshing
Data
getPersistenceMode, queryKeyHolders, refreshState, canDeleteMessages, and the description arrives lazily by size.
Placement
A full-window surface alongside pinned, downloads and server info. It is longer than any of them — the key-ownership block is the part that needs the most room and the most caution.
Standard
components/sidebar/channel/ChannelInfoPanel.tsx
Control

Mute this channel

A channel cannot be silenced. Standard has this on the header menu.

Must show
One menu item that flips between muting and unmuting, and reads as active while muted. A muted channel should also be recognisable in the sidebar without opening it.
States
  • audible
  • muted
Data
toggleSilenceChannel(channelId).
Placement
Header kebab, plus a mark on the sidebar row.
State

New pins and new downloads

Pinned messages and downloads both live behind the kebab, and neither says when something new has arrived. Standard badges the buttons because they are on the header; here the news has to survive being collapsed into a single glyph.

Must show
  • A mark on the kebab when anything behind it is new, distinct from the pressed state.
  • A per-item mark inside the open menu, so the reader knows which of the two to pick.
  • Both clear on open — not on close.
States
  • quiet
  • new pins
  • new downloads
  • both
Data
Flags exist on the store; clearUnseenPins and markDownloadsSeen already do the clearing.
Placement
Header kebab and the menu items inside it.

Message list

The densest zone, and the one where a small drawing decision is felt most often. Four additions and one correction.

Surface

A message that is still sending, and one that failed

Nebula hands the message to the store and forgets it. On a slow link nothing appears until the server echoes it back, and if the send fails there is no row to retry — the text is simply gone.

Must show
  • The message where it will land, at reduced weight, with indeterminate progress — the duration is unknown.
  • On failure: the same row turned to an error, with Retry and Dismiss, keeping the body intact.
  • The row must not shift the conversation when it resolves into the real message.
States
  • sending
  • failed
  • retrying
  • resolved
Data
addPendingPlaceholder, markPendingFailed, retryPendingMessage, dismissPendingMessage. Standard only draws this for messages carrying inline media or large enough to be perceptibly slow — worth keeping, so ordinary text still sends instantly.
Placement
Last row of the conversation, in the message style the user has chosen (bubbles, flat or compact).
Standard
components/chat/pending/PendingMessageItem.tsx
Surface

Clicking a mention

Typing @ in the composer autocompletes. Clicking the resulting mention in a sent message does nothing. Four kinds of mention need two different answers.

Must show
  • A person → the profile card Nebula already draws, anchored to the mention.
  • A role, @everyone or @here → who that resolves to right now, capped at 30 rows with a count of the remainder.
  • Both clamped inside the window with a small gap from the mention and a margin from the edges.
States
  • person
  • role
  • everyone / here
  • resolves to nobody
  • clamped near an edge
Data
Nebula already has the profile card and a point-anchoring helper, so the person case is mostly wiring. The group list is the new drawing.
Placement
Floating over the conversation, anchored to the clicked mention.
Standard
components/chat/mention/MentionPopover.tsx
Control

Who has read this

Nebula shows a read indicator on a message but cannot say who is behind it. Standard puts the list on the message's own menu.

Must show
A list of readers with faces and names, and an honest empty state — "nobody yet" is information, not a failure.
States
  • readers
  • nobody yet
  • many readers
Placement
Inside the message menu rather than as a separate surface, so it stays anchored to the message it describes.
Control

Pop an image out into its own window

Nebula opens images in a lightbox that covers the conversation. Standard can also detach one into a small always-there window, which is what people use to keep a reference visible while they carry on typing.

Must show
One item on the message menu for images. The detached window carries the sender, their face, the caption and the time — that window already exists and is not being redesigned.
Placement
Message menu, next to the existing image actions. Worth a matching control inside the lightbox itself.
Defect

Timestamps ignore the user's date and time settings

Nebula's Language & format page offers 12-hour or 24-hour, a date format, and local-versus-server time — and nothing in Nebula reads any of them. Every timestamp is formatted with the browser's own defaults, so the page appears to work and changes nothing.

Must show
  • Message times, day dividers, the activity log and the lightbox all following the three settings.
  • 12-hour time is wider than 24-hour. Wherever a timestamp sits in a fixed column or beside a name, both have to fit without the layout moving.
States
  • 24h
  • 12h with meridiem
  • auto, from the OS
  • server time
Data
A shared formatter already handles all of this, including asking the OS for its clock format on Windows, where the webview's own answer is unreliable. Nebula formats its own instead.
Placement
Everywhere a time is printed. This is a correction rather than a new drawing, but it changes column widths, so it needs a look.

Settings › Personalize

Nebula's Personalize page covers theme, message style, chat background, channel viewer and interface design. Five settings that Standard offers have no control here — and one of them is already being honoured with no way to set it.

Control

Typeface

Eight typefaces ship with the app and Nebula offers none of them. This is the setting people reach for first when the default is hard for them to read.

Must show
System Default, Inter, Roboto, Space Mono, Monospace, Serif, Humanist and Rounded — each tile set in the face it selects, so the choice is made by looking rather than by name.
Placement
A new group on Personalize. The existing segmented control is too narrow for eight options that each need to show their own face; this wants tiles, like the chat background group.
Control

Text size

Three named sizes plus an exact pixel value for people who want one.

Must show
Small, Medium, Large as the primary choice, with a numeric override available without cluttering the common path. Preview at the size being chosen.
Data
Two fields: the named size, and the custom pixel value used when it applies.
Placement
Beside the typeface group. Bear in mind Nebula's own type scale is fixed — decide what the setting actually scales before drawing it.
Control

Compact mode

A density switch, separate from message style — it tightens the whole client, not just the conversation.

Must show
One switch with a hint that says what tightens. Its relationship to the "Compact" message style needs settling: two controls with the same word are a trap.
Placement
Personalize, near message style — where the ambiguity is visible and can be written away.
Control

Always show message actions

The hover strip on a message appears on hover. This pins it open — an accessibility setting for anyone who doesn't hover reliably, including touch.

Must show
One switch. The pinned strip must not cover the message it belongs to, which is the whole reason it hides today — so the pinned form may need a different position from the hovering one.
Placement
Personalize, with the message style group.
Defect

Background fit — cover or tile

Nebula's chat backdrop already honours a tile-versus-cover setting. Nothing anywhere in Nebula can set it, so it is permanently whatever it was last left at.

Must show
Two options in the chat background group, previewed on the actual image — the difference is invisible on an abstract swatch.
Placement
Inside the existing Chat background group, beside blur, opacity and dim.

Settings › Voice

Nebula's Voice page covers devices, activation, the gate and the calibrator. Three things Standard offers are missing, and one of them is the reason people give up on a microphone entirely.

State

The microphone is busy

When another application is holding the microphone, Nebula shows nothing — the meter simply stays flat. The backend already reports this, names the apps responsible when it can, and pushes an update the moment it changes.

Must show
  • That the microphone could not be opened, and by whom when the names are known.
  • A different, plainer message for a failure that is not a busy device.
  • It clears itself when the microphone frees up — no dismiss button, no stale warning.
States
  • held, holders known
  • held, holders unknown
  • other failure
  • clear
Placement
Above the input device control, where the person is already looking. Standard also surfaces it outside settings, which is worth considering — the mic is usually busy while someone is trying to talk, not while they are in settings.
Standard
hooks/useCaptureError.ts, pages/settings/AudioPanel.tsx
Control

Noise suppression, in detail

Nebula picks the noise-suppression algorithm but exposes none of its knobs. The set of knobs is different per algorithm and comes from the backend, so this cannot be a fixed list of sliders.

Must show
  • One slider per knob the chosen algorithm reports, each with its own range, step and default.
  • Nothing at all for algorithms with no knobs — the group disappears rather than showing an empty box.
  • A way back to the defaults, since these are easy to get lost in.
States
  • knobs
  • no knobs
  • loading the schema
  • changed from default
Data
The schema is fetched per algorithm; values are stored keyed by knob id, with anything missing falling back to that knob's default. Expert mode gates this in Standard.
Placement
Under the algorithm picker, appearing and disappearing as the algorithm changes.
Control

Exclusive microphone access (Windows)

Takes sole control of the input device for lower latency, at the cost of every other application losing it.

Must show
One switch, visible only on Windows, with a hint that states the trade honestly rather than only the benefit.
Placement
With the advanced input controls. This item and the busy-microphone banner are related — turning this on is one way to cause the other.

Connect screen

Control

Fill in the name they already chose

Adding a server opens a dialog whose username field is empty, even though the person set a default name in settings. Standard prefills it.

Must show
The saved default already in the field, selected so it can be typed over in one go. If no default is set the field stays empty and the existing validation stands.
Data
defaultUsername, a preference Nebula already writes on the Profile page.
Placement
Add-server dialog, username field.

Profile card

Surface

Where someone is

A person can put a location on their profile. Standard draws it as a small map on their card; Nebula drops it. Nebula's Privacy page even offers a switch to turn those maps off — a switch that currently does nothing, because there is no map to suppress.

Must show
  • A small map on the profile card, sized to sit under the existing detail rows rather than dominate the card.
  • Nothing at all when the viewer has turned maps off — the row goes, not just the tiles.
  • A resting state before the tiles load, since this is the one part of the card that reaches the network.
States
  • located
  • loading tiles
  • maps disabled
  • no location
Placement
Profile card, below the written detail. The card has both a plain and a styled form and the map has to sit in both.

Not in scope

These are absent from Nebula on purpose and are recorded as such in the pack's own architecture notes. Don't design them without asking first.

  • Live documents
  • Calendar and meetings
  • Scheduled messages
  • Watch together, host side

  • Pasted-image tray

  • Per-message translation
  • Dragging channels and users
  • Focused single-stream view

  • First-run setup wizard
  • Friends page

  • Channel recording
  • Mobile layout
Derived by comparing what each pack's client actually loads — an import graph from NebulaClientApp and standard/App, so anything Nebula borrows from Standard is counted as present — then diffing the backend commands, store actions and preference fields each side reaches. Settings navigation, the whole administration console, the user menu, global search, shortcuts and profile styling all came back at parity and are not in this document.
